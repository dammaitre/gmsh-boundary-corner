# GMSH-BOUNDARY-CORNER

Gmsh fork aimed at providing a working interface for boundary layers intersecting the y- axis at 90°. GMSH's boundary layer generation averages the two neighbooring normal vectors of each point to extend the mesh. The y- axis has its normals oriented downwards, making the BL generation crash at intersections with hard angles. 

Here we create a new `class BoundaryCornerField` handling the BL rotation to critical corners and joining the BL and the axis. Boundary corners are hence expected to be located at stagnation points: they create nice polar meshes with longitudinal geometric cell squeezing down to the critical point.

A reference visualization of the intended mesh structure is available at `local/boundary_corner_sketch.png`, generated by `local/plot_boundary_corner.py`.

## Mesh Strategy — BoundaryCorner

### Physical context

The BoundaryCorner field targets **external axisymmetric CFD meshes** (e.g. OpenFOAM wedge), where a body of revolution (rocket nose, blunt body, nozzle inlet lip) has its profile curve meeting the symmetry axis **at 90°**. In a 2D cross-section:

- **x** = axial direction (along the symmetry axis).
- **y** = radial direction (y ≥ 0 for the upper half-domain).
- **y = 0** = symmetry axis, which is also the lower boundary of the mesh domain.
- **Profile** = body surface, parametrised as a curve from a **StartPoint** (y > 0, somewhere along the shoulder) to an **AxisPoint** (the nose tip, y = 0).
- At the AxisPoint the profile tangent is vertical (90° to the x-axis), so the wall is **perpendicular to the axis** — this is the critical corner.
- The **fluid domain** is entirely **outside** the body (above and to the right of the profile). The solid body occupies the region enclosed by the profile and the axis.

Standard Gmsh boundary-layer generation fails at this corner because it tries to average the inward normals of the last profile point with the axis, producing degenerate or inverted cells.

---

### The fan structure

The BoundaryCorner zone is the portion of the profile between StartPoint and AxisPoint. Inside this zone the mesh is a **structured fan of quadrilateral cells** that:

1. Covers the fluid region immediately outside the body surface from StartPoint to AxisPoint.
2. Grows **outward from the surface** (in the local outward-normal direction), exactly like a boundary layer.
3. Smoothly sweeps the **90° rotation** of the outward normal — from roughly vertical at StartPoint to horizontal at AxisPoint — so that the outermost layer of the fan lands on the axis y = 0 and connects cleanly to the downstream axis symmetry boundary.

The fan has two index dimensions:

| Index | Direction | Distribution |
|-------|-----------|-------------|
| `i = 0 … N_COL` | along the profile (StartPoint → AxisPoint) | geometric in arc length, compressing toward AxisPoint |
| `k = 0 … N_LAY` | outward from surface | geometric in normal distance, fine near wall |

---

### Column distribution along the profile (tangential direction)

Columns must **not** be placed by uniform angular spacing in the parametric coordinate of the curve, because this would create cells of varying arc-length width and would not respect the curvature of the profile.

Instead, column positions are defined by a **geometric progression of arc lengths** along the profile, with the compression directed **toward the AxisPoint** (nose) where the curvature is highest and the cell size must be smallest.

**Arc-length accumulation.** For any parametric curve `(x(t), y(t))`, the incremental arc length is:

```
ds = sqrt( (dx/dt)² + (dy/dt)² ) dt
```

Accumulated from the StartPoint (t = t_start) toward the AxisPoint (t = t_end), this gives `s(t)` with `s(t_start) = 0` and `s(t_end) = S_total`.

For the half-ellipse `(a cosθ, b sinθ)` specifically:

```
ds/dθ = sqrt( (a sinθ)² + (b cosθ)² )
```

integrated numerically from `θ_start` to `0`.

**Geometric column positions.** Let `ε` (EPS_TAN, `< 1`) be the tangential compression ratio. Column boundaries sit at arc lengths:

```
s_0 = 0
s_i = w_0 · (1 − ε^i) / (1 − ε)    for i = 1 … N_COL
s_{N_COL} = S_total  (pinned exactly at AxisPoint)
```

where the first column width is:

```
w_0 = S_total · (1 − ε) / (1 − ε^{N_COL})
```

This yields column widths `w_0, w_0·ε, w_0·ε², …` — each one narrower than the previous, concentrating resolution near the high-curvature nose.

The parameter `ε` connects to the physical parameters exposed in the field API via:

```
ε = (Delta1 / l)^( 1 / (N_COL − 1) )
```

where `l` is the current tangential element size at the StartPoint (estimated from the existing discretisation of the GEdge) and `Delta1` is the desired arc-length of the last column at the nose.

Once the arc-length positions `s_i` are known, the corresponding parametric values `t_i` are recovered by inverting the cumulative arc-length function (e.g. via `numpy.interp` on a finely sampled table).

---

### Layer distribution in the normal direction (radial direction)

Identical to a standard boundary layer:

```
h_k = h_1 · (ratio^k − 1) / (ratio − 1)    k = 0 … N_LAY
H_total = h_1 · (ratio^{N_LAY} − 1) / (ratio − 1)
```

Layer `k = 0` sits on the body surface; layer `k = N_LAY` sits at the outer edge of the boundary layer at distance `H_total` from the surface.

---

### Node positions

Each fan node `(i, k)` is placed at:

```
P(i, k) = P_profile(i)  +  hk[k] · H_total · n̂(i)
```

where:
- `P_profile(i) = (a cosθ_i, b sinθ_i)` is the profile point at column `i`.
- `hk[k] = (ratio^k − 1) / (ratio^{N_LAY} − 1)` is the normalised cumulative layer fraction.
- `n̂(i)` is the **unit outward normal** at `P_profile(i)`.

For the ellipse, the outward normal at angle `θ` is:

```
n̂(θ) = ( b cosθ,  a sinθ ) / ‖ ( b cosθ,  a sinθ ) ‖
```

At `θ = 0` (AxisPoint): `n̂ = (1, 0)`, so the entire last column lies on `y = 0` — it extends along the axis into the downstream domain, which is exactly the desired connection to the axis symmetry boundary.

---

### Quad cell connectivity

Each quad cell `(i, k)` (for `i = 0 … N_COL−1`, `k = 0 … N_LAY−1`) has vertices:

```
V0 = P(i,   k  )
V1 = P(i+1, k  )    ← next column, same layer (along profile surface)
V2 = P(i+1, k+1)
V3 = P(i,   k+1)    ← same column, next layer (outward)
```

Winding must be consistent with the face orientation expected by Gmsh (`MQuadrangle`).

---

### Integration into the pipeline

Because Gmsh's `meshGFace()` calls `GFace::deleteMesh()` internally, any elements injected before 2D meshing are destroyed. The BoundaryCorner therefore operates as a **post-processor**:

1. The standard 2D triangulation runs first on the entire GFace.
2. `buildCornerColumns()` is called after meshing (hook in `Generator.cpp`, after the 2D loop).
3. All triangles whose centroid falls inside the BC zone bounding box (`x ∈ [x_start, x_axis]`, `y ∈ [0, H_total · 1.05]`) are removed, along with orphaned vertices.
4. The fan quads are injected into the GFace.

**Current limitation (step 6):** the boundary between the injected quads and the surrounding triangulation is not yet conforming — the quad nodes do not coincide with existing triangle nodes along the interface edges. Resolving this requires one of: post-injection node snapping, local re-triangulation with the quad-boundary edges as Delaunay constraints, or reverting to a partial pre-mesh approach using embedded edges in the GFace before `meshGFace()`.

### Field parameters summary

| Parameter | Type | Description |
|-----------|------|-------------|
| `CurvesList` | list of int | Tags of the GEdge(s) forming the profile |
| `AxisPoint` | list `[x_a, 0.0]` | Nose tip — where profile meets axis at 90° |
| `StartPoint` | list `[x_s, y_s]` | Beginning of BC zone on the profile |
| `Size` | double | First BL layer height `h_1` |
| `Ratio` | double | Normal-direction geometric ratio (default 1.15) |
| `NbLayers` | int | Number of BL layers in normal direction |
| `NbLengthControl` | int | Columns (outer part of corner zone) over which arc-length transitions geometrically to `ColWidth`; heights stay BL-geometric |
| `NbHeightControl` | int | Columns (inner part, at the axis) of constant `ColWidth` arc-length where heights blend from BL-geometric to uniform |
| `Delta1` | double | Arc length of last column at nose (−1 = use `Size`) |
| `Omega` | double | Global height scaling factor (default 1.0) |

## Building this fork

**Prerequisites:** C++ compiler, CMake, and FLTK (for the GUI). See the original Gmsh readme below for full dependency details.

### First-time configuration

```bash
mkdir -p build && cd build
cmake -DENABLE_BUILD_DYNAMIC=1 -DENABLE_MMG3D=0 ..
```

`ENABLE_BUILD_DYNAMIC=1` is required to produce the shared library used by the Python API (`test_bc.py`). `ENABLE_MMG3D=0` disables mmg3d, which has a pre-existing linker bug in the bundled v4.0 unrelated to this work.

### Build targets

```bash
# Python API — needed for test_bc.py (headless testing)
cd build && make -j$(nproc) shared

# Gmsh binary — needed for --gui visualisation
cd build && make -j$(nproc) gmsh
```

### Running the tests

```bash
python test_bc.py            # headless — prints triangle/quad counts
python test_bc.py --gui      # opens result in gmsh GUI
```

Expected output (H1=0.012, RATIO=1.20, N_LAY=6, W0_MAX=0.06):
- ~289 quadrangles (BL + BC structured quads)
- ~2453 triangles (far-field Delaunay)

Build Gmsh from the command line
--------------------------------

* Create a build directory, for example as a subdirectory of Gmsh's source
  directory:

    mkdir build

* To build the monolithic Gmsh app with the default build options, run cmake
  from within the build directory, pointing to Gmsh's source directory, then run
  "make"

    cd build
    cmake ..
    make

  Optionally running

    make install

  will install the Gmsh app in the standard system location (controlled by
  CMAKE_INSTALL_PREFIX - see below).

* To build the Gmsh app dynamically linked to the shared Gmsh library, which can
  then also be used by external codes through the C++, C, Python and Julia Gmsh
  API, run

    cd build
    cmake -DENABLE_BUILD_DYNAMIC=1 ..
    make
    make install

  This will install the Gmsh app and the shared Gmsh library, as well as the C++
  and C include files and the Python and Julia modules.

* To change build options you can use "ccmake" instead of "cmake", e.g.:

    ccmake ..

  or you can specify options directly on the command line. For example, you can
  use

    cmake -DCMAKE_PREFIX_PATH=/opt/local ..

  to specify the location of external packages installed in non-standard
  directories. You can use

    cmake -DCMAKE_INSTALL_PREFIX=/opt

  to change the installation directory. Or you could use

    cmake -DENABLE_FLTK=0 ..

  to build a version of Gmsh without the FLTK graphical interface. The list of
  all available configuration options is given in the reference manual.

* To see a detailed compilation log use

    make VERBOSE=1


Build Gmsh using CMake's graphical user interface
-------------------------------------------------

* Launch CMake and fill-in the two top input fields (telling where the Gmsh
  source directory is located and where you want the Gmsh binary to be created).

* Click on "Add entry" and define the variable CMAKE_PREFIX_PATH, of type
  "PATH", pointing to the location(s) of any external package(s) (FLTK,
  BLAS/LAPACK, etc.) installed in non-standard directories.

* Click on "Configure" and choose your compiler.

* Optionally change some configuration options (re-run "Configure" every time
  you change some options).

* Once you are happy with all the configuration options, click on "Generate".

* Go to the build directory and build Gmsh using your chosen compiler.
